# Развёртывание

Одно приложение, один процесс, один том. Базы данных нет: вики хранит записи
как markdown-файлы, дерево — как JSON, комнаты совместного редактирования — как
бинарные снимки Yjs. Всё это лежит в `/data`.

| путь        | что отдаёт                    |
| ----------- | ----------------------------- |
| `/`         | публичная вики                |
| `/admin/`   | админка (файловый менеджер)   |
| `/map/`     | карта                         |
| `/geo/`     | запечённая топология провинций|
| `/geo/arcs` | подгрузка деталей при зуме    |
| `/collab/*` | websocket совместной работы   |

## Уровни детализации карты

Карта грузит один обзорный бандл (`lod3`, 1.9 МБ) — этого хватает до z5.
Дальше:

| зум      | откуда геометрия                                        |
| -------- | ------------------------------------------------------- |
| до 5.1   | `lod3`, бандл целиком                                   |
| 5.1–7.1  | `lod2`, бандл целиком (4.2 МБ, догружается фоном один раз) |
| 7.1–10.5 | `lod1`, только дуги в кадре — `POST /geo/arcs`           |
| дальше   | `lod0`, так же по дугам                                 |

Тонкие уровни лежат **не** в `GEO_DIR`: всё, что там, отдаётся статикой, а
`detail-lod1.bin` — это 27 МБ, `detail-lod0.bin` — 54 МБ. Сервер держит в
памяти только таблицу смещений (135 КБ на уровень) и читает из файла нужные
байты.

`detail-lod0.*` не в репозитории — это последнее удвоение точности за 54 МБ,
нужное только при зуме глубже z10. Если нужно, соберите локально
(`tools/geo/stage5_detail.py`) и уберите строку из `.gitignore`; без файла
сервер просто не предлагает этот уровень, а клиент останавливается на `lod1`.

## Сборка образа

Собирает GitHub Actions: `.github/workflows/docker.yml`. При пуше в `main`
образ уезжает в `ghcr.io/<владелец>/<репозиторий>` с тегами `main`, `latest` и
`sha-<коммит>`; тег вида `v1.2.3` даёт `1.2.3`, `1.2` и `latest`.

Репозитория ещё нет — нужно один раз:

```sh
git init && git add -A && git commit -m "Aether: wiki, admin, map"
git remote add origin git@github.com:<владелец>/<репозиторий>.git
git push -u origin main
```

Права на публикацию у workflow уже есть (`packages: write` + встроенный
`GITHUB_TOKEN`), настраивать секреты не нужно.

Образ собирается под `linux/amd64` и `linux/arm64`. arm64 идёт через эмуляцию и
занимает втрое больше времени — если разворачиваете только на x86, уберите его
из `platforms`.

Собрать локально, если есть docker:

```sh
docker build -t aether:dev .
docker run --rm -p 3010:3010 -v aether-data:/data aether:dev
```

## Portainer

**Stacks → Add stack → Web editor**, вставить `docker-compose.yml`, в разделе
Environment variables задать:

| переменная       | значение                                        |
| ---------------- | ----------------------------------------------- |
| `AETHER_IMAGE`   | `ghcr.io/<владелец>/<репозиторий>:latest`        |
| `AETHER_NETWORK` | сеть, в которой живёт nginx proxy manager        |

Сеть подключается как `external` — стек в неё входит, но не создаёт и не
удаляет. Если имя не совпадёт, стек не запустится: это лучше, чем молча
подняться в своей отдельной сети, где прокси его не увидит.

Портов наружу контейнер не публикует — вход только через прокси. Если нужно
достучаться напрямую (например, домена ещё нет), раскомментируйте `ports` в
compose.

Если пакет в GHCR приватный — **Registries → Add registry → Custom**,
URL `ghcr.io`, логин — имя пользователя GitHub, пароль — personal access token
с правом `read:packages`; затем выбрать этот registry при деплое стека.

Обновление: **Pull and redeploy**. Том переживает замену образа — образ несёт
только код и топологию.

### nginx proxy manager

**Hosts → Proxy Hosts → Add Proxy Host**:

| поле                  | значение   |
| --------------------- | ---------- |
| Domain Names          | ваш домен  |
| Scheme                | `http`     |
| Forward Hostname / IP | `aether`   |
| Forward Port          | `3010`     |
| **Websockets Support**| **включить** |

Имя `aether` резолвится по DNS докера, потому что оба контейнера в одной сети.

Websockets Support — не опция, а обязательное условие. Без него `/collab/`
отвечает 400 на upgrade: карта и совместное редактирование подключатся и сразу
отвалятся, при этом обычные страницы будут открываться нормально — симптом,
который легко списать на что угодно другое.

Сертификат — вкладка SSL, Request a new SSL Certificate, Force SSL.

## Что в томе

```
/data
├── records/     запись = один .md файл, имя = слаг
├── rooms/       снимки Yjs, по одному на запись + map-proto
├── uploads/     референсные изображения для карты
└── tree.json    папки, слаги, уровни допуска
```

Бэкап — обычный `tar` этого каталога; сервер пишет `tree.json` через
временный файл с переименованием, так что снимок не поймает половину записи.

Записи — настоящий markdown: их можно грепать, диффать и читать чем угодно.

## Переменные окружения

| переменная  | по умолчанию   | зачем                                        |
| ----------- | -------------- | -------------------------------------------- |
| `PORT`      | `3010`         | порт внутри контейнера                        |
| `DATA_DIR`  | `/data`        | изменяемое состояние (том)                    |
| `GEO_DIR`   | `/app/geo`     | запечённая топология (часть образа)           |
| `GEO_DETAIL_DIR` | `/app/geo-detail` | тонкие уровни, режутся по дугам        |
| `LOG_LEVEL` | `info`         | `debug` показывает каждый запрос              |

## Чего пока нет

Аутентификации. `clearanceOf()` в `backend/src/wiki.ts` возвращает 0 для всех,
то есть **любой, кто откроет `/admin/`, может редактировать**. Пока сервис
авторизации не подключён, не выставляйте это в интернет без внешней защиты —
хотя бы basic-auth на `/admin/` в прокси.
